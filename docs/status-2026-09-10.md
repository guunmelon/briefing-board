## 1. good! 버튼 = “이 뉴스 다 봤다”

| 동작 | 내용 |
|---|---|
| 클릭 | 해당 기사를 **읽음 처리**(`state.readIds`, `tid\|id`) + 취향 기억(`state.likes`) |
| 결과 | 같은 관심사의 **아직 안 읽은 다음 기사**가 그 자리에 온다 |
| 다 읽으면 | `/api/live/news?exclude=…&fresh=1`로 **지금 새 기사**를 실시간 수집해 이어서 표시 |
| 소스에도 없으면 | 그 관심사의 읽음 표시를 초기화하고 처음부터 순환 (빈 카드 만들지 않음) |
| 해제 | good! 다시 누르면 읽음 취소 → 그 기사를 다시 읽을 수 있음 |
| 표시 | 카드 우상단 `읽음 1/4` 칩 · 위 레일 하단 취향 카운터 |

코드: `src/logic.js`(`pickUnread`/`advanceAfterRead`) · `src/app.js`(`currentItem`/`markRead`/`advanceTopic`/`likeStory`)

## 2. 피드백 = 코드를 만들어 반영 (자가 반영 엔진)

### 이전 문제
`planFromFeedback()`이 **미리 정해둔 설정 8종**에서 골라 맞추는 구조 → “날씨를 오전/오후로 나눠서”, “미세먼지도 표시해줘”는 답이 없어 후보 제안만 나왔다.

### 지금 구조
```
피드백 입력(브라우저)
  → POST /api/feedback/apply { text, topics }
  → tools/patch-engine.js  : 문장 → (대상·위치) + 연산자 목록
  → 코드 생성              : src/patches/<id>.js  (BPatch.register(...) 실제 JS 소스)
  → tools/build.js 재빌드   : dist/index.html 에 패치 인라인
  → 응답(생성 코드 전문)     : 모달에 코드 표시 + “지금 새로고침” / “방금 패치 되돌리기”
  → 화면 갱신               : /api/build 해시 워처(15초)가 빌드 변화 감지 시 자동 reload
```
`src/patch-runtime.js`가 렌더 두 지점에 훅을 건다 — `applyData`(payload 가공: 단위·자리수·건수), `applyHtml`(마크업 확장/축소). 패치 하나씩 try/catch → 고장난 패치는 원본 유지 + `BPatch.errors()`에 기록(보드가 깨지지 않음).

### 연산자 9종 (사전에 없는 요청은 “못 한다”고 알린다 — 없는 답을 골라주지 않음)
`split-daypart`(오전/오후·저녁 분리) · `field.add`/`field.hide`(데이터 라인 추가/제거) · `section.add`(시간대 그래프·주간 3일·일출일몰·다음 경기) · `precision`(소수점 자리) · `unit`(화씨/섭씨/km·h) · `rename`(라벨) · `css`(카드 한정 크기·굵기) · `list.count`(목록 건수)

### 위치(스코프) 지정
문장에 위젯을 적으면 그 자리만 고친다 — `일정위젯의 →`(오늘 일정 위젯 날씨 줄 `#wxStrip`) · `카드/타일` · `브리핑/뉴스레터`. 안 적으면 관심사 카드 + 일정 위젯 줄 양쪽에 적용.

### 사용자 예시로 확인한 결과
| 요청 | 생성된 것 | 화면 결과 |
|---|---|---|
| `날씨를 오전/오후로 나눠서 표시해줘` | `weather-split-daypart-*.js` (hourly 실측 집계) | 카드 아래 `오전 18° ~ 16° / 강수확률 33%` · `오후 23° ~ 19° / 69%`, 빗줄 시간대는 강조 |
| `일정위젯의->날씨를 오전/오후로 나눠서 표시 해줘` | 같은 연산자, `scope:"strip"` | 오늘 일정 위젯의 날씨 줄 아래에 동일 블록 |
| `미세먼지도 표시해줘` | `field.add` pm10·pm25 | `미세먼지 PM10 19 ㎍/m³ · 좋음` · `초미세먼지 PM2.5 15 ㎍/m³ · 좋음`(Open-Meteo AirQuality 실측) |
| `화씨로 바꿔줘` / `소수점 1자리로만 보여줘` | `data` 훅(단위·반올림) | 22.4℃ → 72.3℉, 43.46 → 43.5 |
| `비행기 표 예약해줘` | 없음 | `ok:false` + 지원 연산자 9종만 안내, 파일·빌드 무변화 |

### 서버 API
`GET /api/build` · `GET /api/feedback/patches` · `GET /api/feedback/patch?id=` · `POST /api/feedback/plan`(dry-run) · `POST /api/feedback/apply` · `POST /api/feedback/undo {ids}` · `POST /api/feedback/clear`

## 3. 비가 올 때 하늘 — 자동 전환 (실측 기반)

이전엔 `weatherFromMode()`가 **수동 미리보기 버튼**(`state.skyMode`)만 봐서, 실제로 비가 와도 하늘은 바뀌지 않았다(버튼을 눌러야만 보였다). 이제 판정이 UI와 분리됐다:

- `Logic.skyAlertFromWeather(w)` — 실측 payload만으로 `storm > snow > rain > dust > heat > cold` 순 판정
  - 뇌우: 상태명 또는 WMO 95–99 · 눈: 71–77, 85, 86 · 비: 상태명 또는 `precip ≥ 0.1mm` 또는 (`rainPct ≥ 60` && 51–67/80–82)
  - 미세먼지·황사: `pm10 ≥ 150` · 폭염 `≥35°` · 한파 `≤ -12°`
- `Logic.decideSky(mode, alert, hour)` — `auto` + 실측 경보 → 하늘·빗줄기·창유리 물방울 자동 전환/해제, 수동 선택(낮·노을·밤·경보 미리보기)은 사용자 의사를 존중
- 소스: 등록한 날씨 관심사 payload → 없으면 서울 실측(`ensureSeoulWeather`)
- 확인 방법: **☰ 설정 → 배경 하늘** 아래 실시간 판정 줄에 근거가 그대로 보인다 — 예: `실시간 판정: 기온 22° · 강수 0mm · 확률 0% · PM10 19 · 상태 구름 조금 → 경보 없음(시간대 하늘)`. 비가 오면 이 줄이 `→ 비 하늘로 자동 전환됨`으로 바뀐다.
- 전환 순간만 로그에 남긴다(매 틱 반복 알림 없음): `실시간 기상 감지 → 배경 하늘을 비(으)로 전환` / `기상 특보 해제 → 시간대 하늘로 자동 복귀`

검증(test-core 12건 + test-native D 5건): 강수 0.6mm → rain, 뇌우 → storm(비보다 우선), 눈 → snow, PM10 180 → dust, 맑음 22° → 판정 없음, `body.rain` 클래스 + `data-sky=rain` + 그라데이션 팔레트 교체 + 유리창 물방울 노드 생성까지 확인.

## 4. 스포츠 관심사 — 팬 한눈에 카드

분류: 팀·리그가 확인되면 새 종류 **`sport`** (기본 관심사 `맨시티` 포함). 확인 실패·소스 제한 시 뉴스형으로 우회(가짜 일정 금지).

**소스**: TheSportsDB(키 불필요) — 팀 검색 → 리그 id → `eventsday`(리그+날짜)로 최근 5일/앞으로 7일 스캔. 무료 키 슬로틀(429) 대응: 요청 간격 340ms + 1회 재시도 + **60초 쿨다운**(그 사이 뉴스 표시), 리그·날짜별·팀 검색 캐시(최대 12h), 좁은 창에서 시작해 없으면 확장.

**타일(시안 A · 기본)**: `리그·라운드` / `다음이 홈|원정경기` / `D-n + 남은 시간(3일 4시간)` / `홈 vs 원정` / `킥오프` / `경기장` / 진행 중이면 `점수 + NN분 경과 + 구장` / `최근 결과` + `최근 5경기 폼(●W W D L)`
**시안 B**: 다음 3경기 목록(날짜·vs/@상대·구장) **시안 C**: 점수/카운트다운 컴팩트 한 줄
**뉴스레터 카드**: 상태·킥오프 / 경기장 / 최근 결과 / 최근 5경기 4칸 격자 + LIVE 칩
**데이터 연결 전**: `시안 · 경기 데이터 연결 전` 골격(줄마다 `—`) — 숫자를 만들지 않음
