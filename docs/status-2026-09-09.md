## 1. 실행 방법 (지금 브라우저 확인 모드)

```bash
cd briefing-board
node tools/build.js                     # src → dist 단일 파일
node tools/live-server.js --dir dist    # 미니 실시간 서버 (포트 8420)
# → 브라우저에서 http://localhost:8420
```

- 라이브 서버가 없으면(file:// 등) 앱은 숫자·기사를 만들지 않고 **"실시간 연결 필요"** 안내만 표시합니다(원칙 유지).
- Windows 앱(WebView2)은 `window.__BRIEFING_HOST__.apiBase`로 동일 파이프라인을 자동 사용합니다.

### 관심사 추가 흐름 (시안 선택)
1. 보드 헤더(관심사 관리) → 이름 입력(예: `삼성전자`, `걷기`, `서울 날씨`)
2. AI가 종류 분류(주식/개인/날씨 …) → **실데이터가 박힌 시안 3종** 표시(연결 시)
3. 시안 클릭 → 실물 미리보기 확인 → **추가**. 개인형은 수치 없이 "연결 필요".

### "관심없음" 흐름
뉴스레터 카드의 관심없음 → 그 관심사의 `fresh` 새 기사를 수집해 카드 즉시 교체.
같은 소식을 다시 안 주도록 `exclude`(본 ID + 이전 피드)를 서버에 전달.

## 7. 3라운드 반영 (2026-09-09 연장 피드백) — 검증 완료

### 7-1. iCloud 일정표시 스위치 + 일정 갱신 (전용 서버 API 신설로 해결)

**증상**: “확실히 연결됨”까지는 표시되는데 (a) 캘린더를 바꿔도 화면 일정이 갱신되지 않고, (b) **일정 표시** 스위치가 켜지지 않음.

**근본 원인(진단)**: 클라이언트(`app.js`)는 설정창에서 이미 `/api/prefs`를 호출해 스위치를 켜려 했지만, **미니 서버에 `/api/prefs` 라우트가 없어 404** → 스위치가 꺼진 채 남고 `/api/events`도 계속 `enabled:false` → “갱신이 안 된다”처럼 보였음. (UI 로직 문제가 아니라 서버 API 누락.)

**수정 (tools/live-server.js)**:
- `loadPrefs/savePrefs` — `tools/.cache/prefs.json`(mode 600)에 영속. 키: `calendarEnabled · autoStart · topmost · newsPollMinutes · calendarEmail`.
- `/api/prefs` **GET/POST** — POST는 위 키를 병합·저장 후 `{ok, calendarEnabled, newsPollMinutes, calendarEmail}` 반환.
- 자격증명(`/api/credentials` POST) 성공 시 서버가 `calendarEnabled`를 **자동 true**(연결 해제 DELETE 시 false) — 네이티브와 동일 동작.
- `/api/events`는 이제 자격증명 **그리고** `calendarEnabled`가 모두일 때만 활성. 일시 CalDAV 오류는 `{enabled:false, reason:'sync-error'}`.

**수정 (src/host.js)**: `sync-error` 응답 시 기존에 불러온 일정을 **지우지 않고 유지**(빈 화면/연결 CTA로 되돌아가지 않음).

**curl 실측**: `GET /api/prefs` false → `POST {calendarEnabled:true}` → `GET` true → false로 초기화 확인.

**UI 검증 (jsdom, dist 빌드 후)**: 설정 열기 → **일정 표시 클릭 → ON** → 오늘 위젯에 일정 표시(오늘 N건·동기화됨) → mock 캘린더에 새 일정 추가 → **동기화 클릭 → 즉시 반영** → 일시 sync-error 시 기존 일정 유지 — 전부 통과.
